# Формат буфера Zero (как Тильда копирует/вставляет элементы)

Источник: редактор Zero, блок-образец recordid=4539706701 (копия страницы). Проверено на практике: вставка своего буфера по Ctrl+V работает.

## Как вставлять
1. Редактор Zero работает во вложенном iframe (`iframe=y`), JS нужно выполнять в `iframe.contentWindow`. Если Zero открыт напрямую (`tilda.ru/zero/?recordid=…`), то в самом окне.
2. Положить JSON в `localStorage['tn_store_buffer__copy-paste']`:
   `{ "res": 1200, "data": [ …узлы… ], "timestamp": Date.now() }`
3. Кликнуть в пустую область холста и нажать Ctrl+V. Редактор сам создаёт слои, перегенерирует ID, ставит смещение.
4. Сохраняет человек: кнопка «Сохранить» в блоке.

## ID
`t396__getUniqueId()` = `Date.now()` + шестизначный счётчик (`1790848322398000016`). Вручную не придумывать, брать только из этой функции (в iframe). При вставке редактор всё равно перегенерирует.

## Узел
```
{ id, index, type: "element" | "group", isSelected: false, props: {…}, children: [ …только у group… ] }
```
Глубина вложенности групп/автолейаута: не более 6 уровней (правило Тильды).

## Разрешения
Базовое значение = 1200. Для других разрешений суффикс: `top-res-320`, `width-res-320`, `hidden-res-320`, `fontsize-res-320`…
Ширина макета 360 → кладётся в `-res-320` (проверить, как масштабируется).

## Элемент text (основное)
`elem_type:"text"`, `text` (HTML со span), `fontsize`, `color`, `fontfamily` (`playfair_display`, Mazzard, Suisse), `lineheight`, `fontweight`, `letterspacing`, `textfit` (`autowidth`|`fixedsize`|…), `valign`, `tag` (h2|div|…), `top`/`left`/`width`/`height` + `*units:"px"`, `zindex`, `hidden:"n"|"y"`, `layer` (имя слоя).

## Группа с автокомпоновкой
`elem_type:"group"`, `type:"physical"`, `groupid` (id родителя, у корневой пусто), `name`, `container:"grid"`,
`flex:"auto"`, `flexdirection:"row"|"column"`, `flexgapx` / `flexgapy`, `flexalignitems`, `flexjustifycontent`, `flexaligncontent`,
`widthmode`/`heightmode`: `fill`|`fixed`|`hug`, `padding:"0 0 3px 0"`, `margin`, `overflow:"visible visible"`,
рамка: `bordercolor`, `borderwidth:"0px 0px 2px 0px"`, `borderradius`.
Дети группы в автокомпоновке получают `groupid` родителя; `top/left` для них пересчитывает редактор.

## Классы для кастомных скриптов
Поле `classname` у группы или элемента (пример: `border-2-bottom`, `border-05-bottom`). Также есть `tag`, `attributes`. На странице класс попадает на `.tn-elem`, по нему цепляем наши скрипты и стили.

## Что выяснено при сборке «Программы турнира» (проверено)
- **Порядок.** Массив узлов в буфере обратный: index 0 = самый верхний слой и последний в потоке автокомпоновки. `tools/zero-gen/lib.mjs` разворачивает сам, описывать нужно в естественном порядке (снизу вверх / сверху вниз).
- **Холст блока.** Если у артборда включён Auto layout (Flex: Auto), корневые элементы выстраиваются в поток. Для свободных координат поставить Flex = None (`<select name="flex">`, значение `""`) ДО вставки; высота холста — `input[name=height]` отдельно для 1200 и для 320.
- **Две ширины в одном дереве.** Базовые значения = 1200, `*-res-320` = мобильные. Что есть только на одной ширине, дублируется элементом с `hidden` / `hidden-res-320` (`y`/`n`). Общую часть (таблица) держим одним деревом: тексты правятся один раз.
- **Глубина** групп — не более 6 уровней; у текста есть `padding`, поэтому ячейка-обёртка не нужна.
- **Шрифты проекта.** Mazzard Bold = `fontweight: 900` (в @font-face проекта 700 подменён другим файлом!), Light = 300; Playfair — `playfair_display`, 400. Регистр: `lettercase: "uppercase"`.
- **Трекинг (кернинг).** Zero хранит только px (`letterspacing`), проценты не принимает. Из Фигмы проценты пересчитываем: `px = % / 100 × fontsize`, отдельно для каждой ширины, потому что fontsize у 1200 и 320 разный (`letterspacing` и `letterspacing-res-320`). Пример: шрифт 10px, -3% -> `-0.3`; тот же -3% на шрифте 9px -> `-0.27`. Хелпер `lsPx(pct, fontsize)` в `tools/zero-gen/lib.mjs`. Для текста со спанами (индивидуальный трекинг) считается так же для каждой буквы: `letter-spacing: Xpx` в `style` спана. Межстрочный — множитель (120% -> 1.2).
- **Имена слоёв** не должны оканчиваться на число (редактор считает его счётчиком и переименовывает).
- **Картинки по ссылке** работают: `img` = URL (проверено на raw.githubusercontent.com), плюс `filewidth`/`fileheight`.
- **0.5px линии.** Классы проекта `border-05-mobile bottom` (только < 1200) задаёт 0.5px; нативная ширина в Zero целая.
- **Не воспроизводится нативно:** blend modes, шум, backdrop blur, размытые тени. Эффекты запекаются в картинки (фон и шар с тенью).

## Процесс (Фигма -> Тильда)
1. `use_figma` (чтение) даёт точные свойства узлов 1200 и 320; `get_screenshot` — растры с запечёнными эффектами.
2. Картинки в WebP -> `assets-src/` + репозиторий `MiZaRiii/golf-club` (raw-ссылки).
3. `node tools/zero-gen/program.mjs` -> `tools/zero-gen/out/program.json`.
4. В редакторе блока: Flex холста = None, высоты холста; `inject.js`; клик по холсту; Ctrl+V.
5. Проверить 1200 и 320 в редакторе, нажать «Сохранить» (человек).

## Правила сборки блоков скриптом (согласованы)
1. **Дубли для 1200 и 320 — только когда иначе нельзя.**
   - Дубль элемента делаем, только если штатно не получить тот же результат: у текста отличается содержимое или внутренние настройки (спаны с индивидуальным трекингом), либо нужна другая картинка (другой кадр).
   - Во всех остальных случаях это ОДИН элемент со значениями для 1200 и `-res-320`: размер и межстрочный текста, размер прямоугольника/svg, координаты.
   - Элемент есть только на десктопе: не дублируем, а скрываем на мобильной (`hidden-res-320: "y"`).
   - «Программа турнира»: «•» один элемент со скрытием на 320; рамка (Frame) и шар (Ball) по одному элементу (шар из большого `program-ball-1200.webp`, масштабируется; `program-ball-320.webp` не нужен); заголовок — два элемента (на десктопе у букв индивидуальный трекинг); фон — два слоя (разные кадры: 1836x913 и 320x792).
2. **Небольшие правки — скриптом по существующим элементам блока**, без пересборки (быстрее и дешевле по токенам). Механизм изучается и проверяется (см. ниже раздел «Правка существующих элементов»).
3. **Полная пересборка — внутри Zero:** очистить блок (Ctrl+A → Delete на 1200 и на 320, скрытые Ctrl+A не берёт) и собрать заново скриптом, не выходя из редактора и не отменяя изменения. Выход без сохранения (откат на версию назад) только если всё зашло в тупик.
4. Эффекты фона запечены в изображения (фон и шар с тенью). Картинки загружаем в Тильду («Upload to Tilda»), копии в репозитории `MiZaRiii/golf-club` (raw). Сохранение блока всегда нажимает человек. Зерно (grain) поверх сайта — отдельно, в T123. Ширины макета 1200 и 320 (не 360).

## Правка существующих элементов (проверено)
- `elem__setFieldValue(элемент, поле, значение, 'render', 'updateui', разрешение)` — меняет поле у УЖЕ существующего элемента и в DOM, и в хранилище редактора (видно при копировании элемента). Разрешение 1200 (базовое) или 320 (`-res-320`). Пример: `tools/zero-gen/patch.js`.
- Не меняет имя слоя (`layer`/`name`): имена задавать при генерации.
- Элемент находится по `.tn-elem[data-field-layer-value="Имя"]`; удаление: выделить слой в панели слоёв, Delete.
- Для мелких правок (размер, координаты, прозрачность, текст, картинка) использовать это, а не пересобирать блок.

## Что поддерживает `-res-320` (проверено на рамке и шаре)
`top`, `left`, `width`, `height`, `hidden`, `opacity`, `borderwidth` — значения для 320 сохраняются в хранилище и применяются при рендере (на 320 рамка получает свою прозрачность и линию). Поэтому рамка и шар — по одному элементу.
Источник картинки (`img`) один на все разрешения и задаётся на 1200; блок «Image» с кнопкой «Upload to Tilda» в панели виден только на 1200.

## Кернинг: правило (уточнено)
В Фигме трекинг обычно в процентах (например -3%). В Zero такого нет: поле `letterspacing` принимает только пиксели. Поэтому генератор всегда считает `px = pct/100 × fontsize` для каждой ширины отдельно и пишет в `letterspacing` и `letterspacing-res-320`. Формулу не подменять числом «как в Фигме» (-3 не равно -0.3). Пример: размер 10px и -3% дают `letterspacing: -0.3`.

## Типографика и отступы (уточнено)
- **Размер шрифта в Zero только целый.** Округляем, при .5 вниз (7.5 -> 7, 12.5 -> 12, 106.7 -> 107), отдельно для каждой ширины. Хелпер `rhd` в `lib.mjs`, `text()` округляет сам.
- **Кернинг:** px = % / 100 × округлённый размер шрифта, не больше двух знаков после запятой (0.375 не подходит: 12px при -3% даёт -0.36). `text({ lsPct })`, хелпер `lsPx`.
- **У текста не использовать `padding`:** в панели Zero такого поля нет, значение нельзя изменить инструментами редактора. `lib.text()` кидает ошибку при `padding`. `margin` у текста работает криво, использовать осторожно. Отступы и gap делаются на группах автокомпоновки (padding и gap групп работают отлично и есть в панели): нужен отступ вокруг текста — оборачиваем текст в группу с padding (лимит вложенности 6 уровней).
- Координаты и размеры в буфере целые.

## Серийный перенос блоков (сценарий)
1. Пользователь сохраняет готовый блок, выходит, дублирует его (так сохраняются настройки Zero), открывает копию, присылает recordid.
2. Claude читает секцию в Figma (по именам в страничных фреймах 1200 и 320), описывает спецификацию, генерирует буфер, очищает блок внутри Zero, выставляет Flex/высоты артборда, вставляет скриптом.
3. Картинки: «Upload to Tilda» по каждой, адреса в профиль/генератор.
4. Сверка с Figma на обеих ширинах, остановка на проверку; правки на месте (`elem__setFieldValue`), без пересоздания, без лишних дублей. Сохраняет пользователь.
5. Отступы между блоками: отдельный пустой Zero-блок под отступ либо padding самого Zero, если внутри автокомпоновка с автовысотой контейнера.

## Зеркало и скрипты
Зеркало опубликованной тестовой страницы (sync.py) нужно для разработки скриптов и эффектов на классах; проверенная логика переносится в T123/HEAD, контент остаётся в Zero. Процесс и правила переноса описаны в навыке `figma-to-tilda-zero`, профиль проекта хранится локально (`profile.json` не публикуется).

## Порядок слоёв и свободные группы (проверено на «Амбассадорах»)
- Порядок массива в буфере: дети группы с автокомпоновкой — обратный потоку; дети СВОБОДНОЙ группы (`flex: ""`) — снизу вверх, последний сверху (z-index внутри группы не работает), без разворота; корень при автокомпоновке артборда — порядок потока без разворота; корень при свободном артборде — обратный (index 0 = верхний слой). `finalize(roots, null, { rootAutolayout: true })`.
- У свободной группы дети хранятся в АБСОЛЮТНЫХ координатах (относительно артборда), размер группы = bbox ВСЕХ детей, включая скрытые на этой ширине. После вставки геометрию детей нужно выставить скриптом (`zg-editor.js: fixFreeGroups`), у скрытых на ширине детей задавать геометрию внутри границ группы.
- `overflow: "hidden hidden"` у группы обрезает детей (контейнер с фото).

## Автокомпоновка артборда (проверено)
- Поля панели «Auto layout» артборда хранятся отдельно для 1200 и 320: `flex` (`""` None, `auto`), `flexdirection` (радио `column`/`row`/`wrap`), gap (для колонки поле `flexgapy`, для строки `flexgapx`), `paddinghorizontal`, `paddingvertical`, `heightmode` (`hug` = Auto, `""` = Fixed). Задаются через `select[name=…]`/`input[name=…]` + события input/change/blur.
- Переключение ширины из JS: `zero.core__switchResolution(1200|320)`. Выделение элемента (в т.ч. скрытого): `elem__select(элемент, false)`.
- Очистка блока (Ctrl+A → Delete) сбрасывает высоту артборда в Fixed 0: потом снова `heightmode=hug`.
- Реализовано в `tools/zero-gen/zg-editor.js` (`setArtboard`, `inject`, `fixFreeGroups`, `uploadImages`).

## Создание блоков на странице из Claude (проверено)
- Редактор страницы `tilda.ru/page/?pageid=…`: у каждого блока при наведении иконки: дублировать, удалить, скрыть, вверх/вниз; плюс «+» между блоками открывает библиотеку («Нулевой блок», «Другое → HTML-код» = T123).
- Новый «Нулевой блок» создаётся с настройками экранов по умолчанию (360/480/640/960/1200, выравнивание Center, фон белый), не как у наших (320/1200, Top, Autoscale). Поэтому новые Zero-блоки делаем ДУБЛИРОВАНИЕМ существующего и очисткой; пустой созданный блок удалять.
- T123: кнопка «Контент» открывает редактор Ace; значение задаётся `ace.edit(document.querySelector('.ace_editor')).setValue(html, -1)`, затем «Сохранить».
- Zero-блок, который меняли в редакторе, мог оказаться сохранён на странице без нажатия «Сохранить» (автосохранение); новый дубликат берёт именно сохранённую версию.

## Быстрый путь сборки (одной командой) и ускорение процесса
Раньше блок собирался десятками вызовов с переключениями и проверками. Теперь:
1. Один раз за вкладку: `eval(await (await fetch("http://localhost:8080/tools/zero-gen/zg-editor.js")).text())` (определяет `window.ZG`).
2. `await ZG.rebuild("<имя>")` делает всё: ждёт загрузки редактора (и сам отказывается от окна «найден локальный черновик»), очищает блок (синтетические Ctrl+A/Delete на 1200 и 320), выставляет артборд (flex, направление, gap, padding, раздельные top/bottom через «Differ», heightmode Fixed→Hug для пересчёта), кладёт буфер и вставляет (синтетический Ctrl+V), снимает выделение (клик по `.tn-floor`), возвращает `fill` корневым группам (редактор делает их `fixed`), выставляет геометрию детей свободных групп, повторно пересчитывает высоту. 20–30 секунд.
3. Дальше ОДИН контрольный просмотр: по скриншоту на 1200 и на 320 (через `ZG.res(320)`), без цепочек промежуточных проверок. Правки на месте: `ZG.patch([["Слой","поле","значение",1200|320], ...])`.
Правила процесса: сначала готовим спецификацию и meta (`out/<имя>.json`, `out/<имя>.meta.json`), потом собираем одним вызовом; не переключаться туда-сюда без нужды; не создавать пробные вставки «посмотреть» (экономия — собирать сразу набело); картинки загружать один раз и вписывать адреса в генератор.
Окно «локальная версия блока» при открытии блока: отказ («Cancel») загружает серверную версию.

## Отступы между блоками (правило)
Блоки на автокомпоновке артборда: отступ до следующего блока закладываем в padding самого Zero. Снизу = расстояние до следующего блока в макете (десктоп; у «Амбассадоров» 97), сверху 0 (его даёт предыдущий блок). На 320 берём padding фрейма из макета (там у секций 48/48). У блоков со свободной раскладкой (фиксированная высота) отступ добавляется к высоте артборда либо отдельным пустым Zero. В `meta.artboard` задаётся `paddingtop`/`paddingbottom`.

## Одна пара картинок на карточку и на сцену
Для слайдера: в карточке один фон и один вырезанный спикер, оба используются и на 1200, и на 320. В сцене по одному слою `BG` и `Person` с геометрией на каждую ширину (`cover`, `imageposition` на 320 `right center` у спикера, чтобы не срезать). Свободная группа не должна содержать детей, выходящих за её границы (размер группы = bbox детей).

## Кнопки и анимация в опубликованном виде (баги, исправленные в скрипте слайдера)
- Прозрачность Zero задаёт на внутреннем слое группы (`.tn-molecule`): менять нужно её, а не группу.
- Многие пользователи Windows отключают «эффекты анимации» (prefers-reduced-motion): по умолчанию анимацию не отключаем (`respectReducedMotion` false).
- Анимации (WAAPI) замирают в неактивной вкладке: тестировать только в видимой.

## Уроки по скриптам поверх Zero (слайдер амбассадоров)
- Стили Zero у элементов часто с `!important` (например `position: relative`): inline-стили скрипта без `!important` не применятся. Призрак-копию для анимации задавать через `style.setProperty(k, v, "important")` с `position:absolute`, иначе она встаёт в flex-раскладку и сжимает настоящий элемент.
- Одинаковые классы встречаются в разных блоках (копии блоков): искать элементы сцены внутри своего `.t-rec`, а не по всему документу.
- Для мобильного кадрирования, недоступного в панели Zero на 320 (привязка картинки), использовать CSS-класс скрипта (`@media`, `object-position`).
- Тонкие линии: класс `border-05-bottom` вешается генератором автоматически на группы с нижней линией 1px макета (`lib.group`); в опубликованной тестовой странице глобального правила на этот класс не оказалось: проверять и при необходимости добавить в T123 страницы.
- Тесты скриптов делать на реальной разметке: скачать опубликованную страницу (User-Agent браузера), подменить T123 на локальный скрипт; для мобильной раскладки грузить страницу в iframe 400 px.
