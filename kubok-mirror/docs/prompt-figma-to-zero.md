<context>
Проект: сайт Кубок Синергии (Golf Club), Tilda, макеты Figma 1200 и 320. Есть локальное зеркало страницы (kubok-mirror: sync.py, serve.py, custom/), генератор `tools/zero-gen`, формат буфера Zero (Ctrl+V), правки существующих элементов через `elem__setFieldValue`. Контент остаётся в Zero (правится в Tilda), поведение и эффекты делаем скриптами на классах (T123/HEAD), отлаживаем на зеркале.
</context>

<constraints>
Типографика и числа
- Кернинг: в Zero только px. `px = % / 100 × fontsize`, отдельно для каждой ширины, не больше двух знаков после запятой (0.375 не подходит).
- Размер шрифта в Zero только целый: округлять вверх/вниз по обычному правилу, при .5 округлять вниз; кернинг считать от уже округлённого размера.
- Для текста НЕ использовать `padding` (его нельзя править в панели Zero). `margin` у текста работает криво, пользоваться осторожно. Отступы и gap делать на группах автокомпоновки (там работают отлично): нужен отступ вокруг текста — оборачиваем в группу с padding.
Структура
- Автокомпоновка Figma переносится как автокомпоновка (корень секции на Auto layout = автокомпоновка артборда, абсолютные элементы вне потока), свободные элементы остаются свободными. Вложенность групп до 6 уровней.
- Порядок слоёв как в Figma. Сложные эффекты (blend, шум, blur, тени, градиенты) запекать в картинку из Figma.
- Дубли для 1200/320 только если иначе нельзя (другое содержимое текста или внутренние настройки вроде спанов с трекингом, другая картинка). Иначе один элемент со значениями для 1200 и `-res-320`. Только на десктопе — скрывать `hidden-res-320`, не дублировать.
- Отступы между блоками: либо отдельный пустой Zero-блок под отступ, либо padding самого Zero, если внутри всё на автокомпоновке с автовысотой контейнера.
Процесс
- Малые правки — скриптом по существующим элементам (`elem__setFieldValue`), не пересобирать, лишних дублей не создавать. Полная пересборка — очистка внутри Zero (Ctrl+A → Delete на 1200 и на 320) и вставка заново, без выхода из редактора. Откат выходом без сохранения только в тупике.
- Картинки загружать в Тильду («Upload to Tilda»), копии в репозитории проекта. Ширины макета 1200 и 320.
- Сохранять существующую вёрстку и дизайн; ничего не сохранять, не публиковать и не менять на боевой странице без явного поручения. Сохранение блока всегда нажимает пользователь.
- Правила конкретного проекта (например классы `border-05-bottom` для 0.5px линий) держать в профиле проекта, не в общем навыке.
</constraints>

<process>
Серийный перенос блоков (цикл на каждый блок):
1. Пользователь сохраняет готовый блок, выходит, дублирует его (чтобы сохранить настройки Zero), открывает копию и сообщает recordid.
2. Claude читает секцию в Figma (1200 и 320; секции находятся по именам в страничных фреймах), готовит спецификацию, генерирует буфер, очищает блок внутри Zero, вставляет скриптом, выставляет Flex/высоты артборда.
3. Claude быстро проходит по картинкам и нажимает «Upload to Tilda», записывает URL в профиль.
4. Claude сверяет результат со скриншотами Figma на обеих ширинах и останавливается на проверку пользователя.
5. Если есть замечания — правки на месте существующих элементов, без пересоздания. Затем следующий блок.
Навык и среда:
- Оформить всё как навык Claude с готовым сценарием: профиль проекта (`profile.json`), шаблоны зеркала (sync/serve/custom), библиотека генератора, процесс, ловушки редактора.
- Сборка блоков на зеркале: на зеркале разрабатываются и проверяются скрипты и эффекты; готовая логика переносится в Tilda в T123/HEAD, контент заносится в Zero навыком.
- Правила записать в docs/zero-buffer-format.md, в память проекта и в навык.
</process>

</output>
